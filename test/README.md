# test

앱과는 상관없는 개발용 도구다. `index.html`은 이 폴더 없이도 그대로 돌아가고,
GitHub Pages 배포에도 아무 영향이 없다. 지우고 싶으면 `test/`, `package.json`,
`.gitignore`를 지우면 끝이다.

## 왜 있나

`index.html`을 고칠 때마다 손으로 30번 탭하고, 업그레이드 사고, 코인 보내고,
랭킹 탭까지 확인하는 게 CLAUDE.md의 규칙이다. 그건 계속 해야 한다 —
자동 테스트는 **눈으로 보는 것을 대신하지 못한다**. 다만 매번 12개 도시를
전부 눌러볼 수는 없어서, 회귀(예전에 되던 게 조용히 깨지는 것)만 기계에 맡긴다.

브라우저 없이 jsdom으로 진짜 DOM을 띄우고, 실제 `pointerdown`/`click`
이벤트를 쏴서 확인한다. 앱이 세 파일로 나뉘어 있는데 jsdom은 `<link>`와
`<script src>`를 동기로 못 읽어서, 각 테스트 파일 맨 위에서 세 파일을 합쳐
넣는다. 파일 이름을 바꾸면 테스트가 즉시 전부 깨진다.

## 실행

```
npm install     # 처음 한 번 (jsdom 받음)
npm test
```

## 무엇을 보는가

- `core.test.js` (37개) — 기본 흐름: 도시 선택 → 탭 45회 → 업그레이드 구매 →
  코인 송금 → 랭킹. 그리고 재난 발생 시 Support 최상단 고정·3분 카운트다운·
  효과 2배·빨간 점·만료 후 원상복구.
- `city.test.js` (372개) — 역할별 탭 의미(배출 감축 / 방어력 축적 / 둘 다),
  My City 한 페이지 통합, 도시 12곳의 업그레이드 이름, 스페이스바 탭,
  리워드 광고(무료 송금·재난 복구·1분 간격·하루 10회·옛 저장 호환).
  도시별 풍경은 그림이라 여기서 못 본다 — 스크린샷으로 확인(HANDOVER 0절).
  그리고 Voice 탭: 역할에 맞는 질문, 도시 12곳의 선택지 4개, 집계 합이 정확히 100,
  의견이 Support·Ranking 어디에도 안 새는 것, **초당 갱신이 입력칸의 문장을 안 지우는 것.**
  그리고 오프라인 수익: 하루치 절반 천장, 3일 비운 것 = 10시간 비운 것,
  **백그라운드 탭이 닫은 탭보다 이득이 아닌 것**, 옛 저장에 지급 0.
  그리고 하루 보드: 여섯 도시가 하루를 다 채우면 **전부 정확히 70**,
  마지막 30은 밖으로 나간 코인으로만 차는 것, 무료 광고 10회 = 만점,
  자정에 보드만 0이 되고 누적·업그레이드는 남는 것, 인구를 1000배 해도 점수 불변.
  그리고 방벽: **600탭 + 자기 코인 전부 = 40%로 안전선(50%)에 못 닿는 것**,
  천장에서 버튼이 사라져 코인·광고가 헛되이 안 쓰이는 것, 매일 10포인트 감쇠,
  외부 구호만 천장을 넘는 것.

`city.test.js`에는 규칙을 못 박아둔 검사가 하나 있다. 업그레이드 이름에
`your / household / turn off / recycle / walk` 같은 단어가 들어가면 테스트가
깨진다. **개인 행동이 아니라 도시 인프라만** 다룬다는 원칙을 사람이 잊어도
기계가 기억하게 해둔 것이다.
